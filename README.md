# Capital Pro | Phuket — Агентский бот (Этап 1)

Новый бот для агентов: каталог с ценами из price-таблицы, регистрация агента,
заявки с привязкой к агенту, админ-панель для вас (CRUD объектов).

## Что нового по сравнению со старым ботом

- Данные объектов теперь в **базе данных (Postgres)**, а не в файле на GitHub —
  редактируете прямо в Telegram через админ-панель, без деплоя
- Агент один раз указывает имя/агентство — бот его запоминает
- В заявке видно, какой агент её привёл (для расчёта комиссий)
- В боте оставлены только 27 объектов, которые есть в Service_South.xlsx

## Шаг 1. Создать нового бота в Telegram

1. Напишите @BotFather → `/newbot`
2. Придумайте имя и username (например `capitalpro_agents_bot`)
3. Получите токен вида `123456:ABC-DEF...` — это `AGENT_BOT_TOKEN`

## Шаг 2. Добавить Postgres на Railway

1. В вашем проекте на Railway нажмите **+ New** → **Database** → **PostgreSQL**
2. Railway сам создаст базу и переменную `DATABASE_URL` — она понадобится сервису бота

## Шаг 3. Создать сервис агентского бота на Railway

1. **+ New** → **GitHub Repo** — создайте новый репозиторий (например `capital-pro-agent-bot`)
   и загрузите туда все файлы из этой папки (main.py, db.py, config.py, handlers.py,
   keyboards.py, requirements.txt, properties_data.py)
2. В Railway подключите этот репозиторий как новый сервис
3. Во вкладке **Variables** нового сервиса добавьте:
   - `AGENT_BOT_TOKEN` = токен из шага 1
   - `DATABASE_URL` = там же можно сослаться на базу через "Reference Variable" на Postgres-сервис
     (Railway это подсказывает автоматически при добавлении переменной)
   - `AGENT_LEADS_CHAT_ID` = chat_id, куда должны падать заявки от агентов
     (можно временно вписать ваш личный ID, потом заменить на групповой)
   - `ADMIN_TELEGRAM_ID` = ваш личный Telegram ID (2133140905) — только у вас будет
     доступ к админ-панели
4. Команда запуска (Start Command): `python main.py`

## Шаг 4. Применить схему базы данных

Нужно один раз выполнить `schema.sql`, чтобы создать таблицы. Проще всего — через
вкладку **Data** у вашего Postgres-сервиса на Railway (там есть SQL-редактор):
откройте, вставьте содержимое `schema.sql`, выполните.

## Шаг 5. Проверить

Ничего переносить вручную не нужно — бот сам при первом запуске проверяет,
пустая ли база, и если да, автоматически загружает туда все 27 объектов из
`properties_data.py`. Просто дождитесь, пока сервис на Railway задеплоится
("Deployment successful" / статус ACTIVE), и переходите к проверке ниже.

1. Напишите вашему новому боту `/start`
2. Первый раз бот попросит представиться (имя, агентство, контакт) — это
   тестовая "регистрация агента"
3. Зайдите в Каталог → убедитесь, что видно 27 объектов с ценами
4. Оставьте тестовую заявку — она должна прийти в чат `AGENT_LEADS_CHAT_ID`
5. Как админ (`ADMIN_TELEGRAM_ID`) — в главном меню появится кнопка
   "⚙️ Админ-панель": добавление/редактирование/удаление объектов,
   быстрая смена статуса (доступен/забронирован), список агентов со
   статистикой по заявкам

## Формат ввода цен в админ-панели

При добавлении объекта бот попросит вставить все 11 периодов одним сообщением
в формате:

```
Январь:210000/7000
Февраль:180000/6000
Март:135000/4500
Апрель:66000/2200
Май:54000/1800
Июнь–Август:48000/1600
Сентябрь:45000/1500
Октябрь:66000/2200
Ноябрь:96000/3200
1–15 декабря:150000/5000
15–31 декабря:210000/7000
```

где `месяц/ночь` — цена за месяц и за ночь в THB.
